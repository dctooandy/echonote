# 會議紀錄匯出成 HTML 開發紀錄

分支：`feature/html-export`
狀態：已完成（實機確認），待併入 master

把一場已分析的會議匯出成一個 HTML 檔，用系統分享選單傳給沒有 EchoNote 的人；「複製摘要」也補上「與上次相比」（跨會議記憶留下的待辦）。這是 2026-10-30 定案路線的第 ④ 步。規格：[`docs/specs/feature-html-export/`](../specs/feature-html-export/feature-html-export.md)。

## 目標

- 「⋯」選單新增「匯出會議紀錄」，產生單一 HTML 檔並打開分享選單。
- 樣式固定一種（使用者從三種範例選了 B 卡片式），不給設定。
- 不放筆記、AI 補充說明、逐字稿、時間戳記。
- 複製摘要包含與上次相比。

## 踩到的坑

### `dart format` 把整個畫面檔重排

**現象**：跑 `dart format` 之後，`meeting_detail_screen.dart` 多出 374 行跟這次無關的改動。

**原因**：這個檔案沒有照 `dart format` 的預設寬度排過；格式化工具會整檔重排。

**修法**：還原畫面檔，重新套用修改、不跑格式化（剩 53 行改動）。新檔案（`meeting_html.dart`、測試）可以格式化。之後改既有的大檔案，不要整檔跑 `dart format`。

### widget 測試裡，寫暫存檔要「等一下再 pump」反覆做

**現象**：測試按「匯出會議紀錄」後，用 `tester.runAsync` 等分享被呼叫，5 秒逾時。

**原因**：寫檔是真的 IO，它的後續步驟排在測試的假時鐘裡；只在 `runAsync` 裡等，假時鐘不會前進，畫面永遠走不到分享那一步。

**修法**：迴圈「`runAsync` 等 20 毫秒 → `pump`」，直到分享被呼叫（最多 100 次）。

### 示意頁的星期寫錯

示意頁寫「2026-11-01（六）」，實際是星期日。單元測試抓到；App 用 `DateTime.weekday` 算，是對的。

### LINE 不收 `.html`

實機分享到 LINE 時顯示「含有無法分享的檔案」；AirDrop、Email 正常。規格決定 12 預期到這個風險，這一版不處理。
