# 分析前標出詞庫的同音寫法 開發紀錄

分支：`feature/glossary-homophones`
狀態：已完成（prompt `4545159f` 已部署、實機確認），待併入 master

`fix/glossary-owner` 之後還剩一個問題：同一份逐字稿裡「小美」「小眉」都出現時，Haiku 4.5 會當成兩個人。prompt 改不動，所以改在程式裡處理：分析前用拼音找出逐字稿中跟詞庫讀音相同的寫法，送給模型時直接註明。規格：[`docs/specs/feature-glossary-homophones/`](../specs/feature-glossary-homophones/feature-glossary-homophones.md)。

## 目標

- 詞庫裡的詞，逐字稿寫成同音的其他字時，分析結果一律用詞庫的寫法、同一個人只列一次。
- Haiku 4.5 不可以變差。

- **還沒做**：讀音相近（捲舌、前後鼻音）不算同音；英文詞（Meetup／Mid-Up）不比對。

## 踩到的坑

### prompt 改不動的，改在程式裡做

**現象**：`fix/glossary-owner` 第 1、2 版 prompt 都寫了「讀音相同的名字視為同一個人」，C7 仍是 1/5。

**原因**：模型要自己發現「小眉」唸起來跟「小美」一樣，Haiku 4.5 做不到；但這件事程式用拼音就能確定。

**修法**：程式找出同音寫法，在 `<glossary>` 那一行註明「小美（逐字稿裡也寫成：小眉）」；模型只要照著替換。第 1 版就 1/5 → 5/5。

### 只叫名字的人名要拆開比

逐字稿常只叫名字（「一針」），全名「蔡宜蓁」三個字比不到。三個字的詞另外用後兩個字比；被全名比對到的位置不再算一次，避免「蔡醫真」同時被記成「蔡醫真」和「醫真」。

### 多音字要整段一起轉拼音

一個字一個字轉，多音字會讀錯；整段逐字稿一起轉，`pinyin-pro` 才會照上下文判斷。代價是要確認轉出來的拼音跟字一一對齊，對不齊的段落直接跳過。

## 合併說明（2026-11-02）

範圍：整個分支

### 改了什麼

- 分析會議前，程式會找出逐字稿裡跟詞庫同音、但寫錯字的地方（例如詞庫有「小美」，逐字稿寫成「小眉」），先告訴 AI 這兩個是同一個。
- 結果：同一個人不會因為逐字稿寫法不同被列成兩個人；待辦負責人和出席者都用詞庫的寫法。

### 怎麼證明能用

- **評測**：Haiku 4.5 全部案例各 5 次，整體 98% → 99.8%；同音名字的案例（C7）1/5 → 5/5；沒有任何一項退步。
- **實機**：部署後分析帶同音寫法的會議，負責人和出席者都正確、只列一次。
- **測試**：functions 46 個全部通過。

### 出事能不能退回

**雙向門**：只改了送給 AI 的內容和說明，資料格式不變。`git revert` 後重新部署 function 就能復原；已經分析過的會議不受影響。
**影響範圍**：會議分析——有設定詞庫的會議。
