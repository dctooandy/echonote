# 詞庫套用到所有欄位、讀不通的詞依上下文推斷 規格

分支：`fix/glossary-owner`
狀態：已完成（2026-11-02，第 2 版 `41da1d10` 已部署，實機確認），待併入 master

Haiku 5.5 評估（`feature-haiku-5-5-eval`）發現兩個有規律的錯，Haiku 4.5 也偶爾會犯：

1. **詞庫只套用到出席者，沒套用到待辦負責人**：C3 的出席者寫「蔡宜蓁、吳承翰」，待辦負責人卻照逐字稿寫「一針」「乘汗」（4.5 1/3、5.5 0～2/3）。
2. **讀不通的詞不推斷**：逐字稿「新網欲」，4.5 推成「網域」，5.5 常寫「申請相關事項（逐字稿內容不清楚）」。

這個分支只改 prompt 把這兩條寫清楚，先確定 Haiku 4.5 不變差再部署；之後用同一份新 prompt 重新比較 4.5 和 5.5。

## 現況

- `SYSTEM_PROMPT`（`functions/src/analyze.ts`）：
  - 第 208 行：「逐字稿可能包含轉錄錯誤……遇到讀不通的內容時盡量根據上下文推斷語意，不要編造逐字稿中沒有的資訊。」
  - 第 210 行：「<glossary> 裡的詞是正確寫法。逐字稿中發音或字形相近的錯字（例如「太基電」應為「台積電」），在所有輸出中一律改用詞庫的寫法。但不可把逐字稿沒有提到的詞庫詞寫進輸出。」
- 評測集只有 C3 帶詞庫。
- 最近的 4.5 基準：`20261102-0812_claude-haiku-4-5`（3 次，98%）。

## 目標與範圍

1. 第 210 行寫明「所有欄位」包含哪些：摘要、待辦的內容和負責人、會議紀錄的出席者／議題／決議、與上次相比、AI 補充說明；人名只出現名字時（例如只叫「宜蓁」）也要對應到詞庫的寫法。
2. 第 208 行補上：發音或字形相近、在上下文裡明顯是某個常見詞時，寫成那個詞；真的推斷不出來才照逐字稿原字寫，不要寫「內容不清楚」這類說明。
3. 新增一筆詞庫案例（見待確認 2），確認修正不是只對 C3 有效。
4. 先用 Haiku 4.5 量修改前、修改後（各 5 次），達標才問使用者部署。
5. 部署後，用新 prompt 跑 Haiku 5.5（low、medium 各 5 次），跟修改後的 4.5 比，結果寫進評測紀錄；換不換模型另外決定。

**明確不做的事**：不改 App、不改 schema、不換模型、不動跟這兩條無關的規則。
