# 會議結論一鍵複製成 LINE 訊息 規格

分支：`feature/meeting-to-line`
狀態：開發中（2026-11-04，決定 1～10 確認）

使用者每週一開完進度會議，要傳一則 LINE 給對方：「本週要做的事＋您已決定的事項」。現在只能自己從摘要、待辦、紀錄分頁拼湊。這個分支讓詳細頁可以直接產生這則訊息，看過、改過再複製。週報另開分支，不在這裡做。

## 現況（寫規格時查過的程式碼和資料）

- 分析結果已經有需要的資料：`MeetingAnalysis` 的 `todos`（`task`、`owner`、`dueDate`、`done`）、`agendaItems[].decisions`、`followUp`。
- 詳細頁的複製：`_copy`（`meeting_detail_screen.dart`）寫剪貼簿並顯示「已複製到剪貼簿」；摘要卡片右上有「複製摘要」（`summaryCopyText`，`lib/services/meeting_html.dart`）。「⋯」選單有「匯出會議紀錄」，沒有分析時停用。
- 使用者的名字：`AppSettings.myName`（`feature/my-name`），用來分出「我的待辦」和「對方的待辦」。

### 用 C8 最新一輪（`20261102-1658`，prompt `9f4247e6`）看實際資料

- **`decisions` 混了不是決定的東西**。真的決定（「地圖全部開放」「優先順序確定：……」）旁邊，還有現況（「平台測試計畫已排定」「測試裝置已準備」）和工作分配（「Andy 下週前準備測試帳號」「請行銷尋找兩家試用商家」）。直接放進「您已決定的事項」會多 3～5 條，跟待辦重複。
- **`dueDate` 是自由文字**：「本週三前」「本週內」「下週」「下週以前」「隔週五跟週報一起」「每週」「未指定」、null。
- **`owner` 大多是 Andy**，對方的待辦常寫成「行銷」，或是空的。
- 待辦有時沒寫出工具名稱：實機那次寫「隔週五發測試版」，沒有 TestFlight。

## 目標與範圍

1. 詳細頁可以從分析結果產生 LINE 訊息，先顯示、可以改，再複製。
2. 訊息固定格式：問候、【您已決定的事項】、【本週要做的事】、【之後】（決定 1）。
3. 訊息用程式從分析結果組出來，不多呼叫一次 AI（決定 4）。
4. 收緊分析的 `decisions`，只留真正的決定；待辦和決議保留工具名稱（決定 3、5）。

**明確不做的事**：不直接呼叫 LINE API 或開 LINE 分享（只複製，使用者自己貼）、不做週報、不把訊息存起來（每次重新產生）、不改匯出 HTML 的版面。

## 組訊息的規則（草稿）

純函式，放在不依賴 Flutter 外掛的檔案，方便測試。

- **決定**：所有 `agendaItems[].decisions` 依序編號；內容完全相同的只留一條。
- **待辦分組**：已勾選完成的不列。
  - `owner` 是使用者的名字或空的 → 我的待辦。
  - `owner` 是別人 → 標「（麻煩您）」（決定 7）。
- **本週或之後**：`dueDate` 含「下週／下周／下禮拜／隔週／下個月」的放到「之後」；但「下週前」「下週以前」是這週內要完成，留在本週。其他（包括沒有期限）都算本週。
- **期限**：接在待辦後面，例如 `・修好審核問題（本週三前）`；沒有期限或是「未指定」就不寫。
- 某一段沒有內容就整段不出現。

## 邊界案例與例外處理

- **分析結果過時**（逐字稿改過、接續的會議換過）：決定 8。
- **舊的分析**：`decisions` 還是混雜的，重新分析才會變乾淨；訊息可以先手動改。
- **沒填「我的名字」**或這場沒勾「我有參加」：分不出誰是我，決定 7。
- **沒有任何決定也沒有待辦**：入口仍可按，預覽顯示提示，不能複製空的內容（決定 8）。
- **訊息很長**：LINE 單則上限 5,000 字，C8 這種會議約 300～500 字，不特別處理。

## 測試接縫

- **純函式**：決定編號與去重；我的／對方的待辦分組；「下週」和「下週以前」的判斷；完成的待辦不列；空的段落不出現；期限顯示。
- **widget 測試**：沒有分析時入口停用；預覽顯示組好的文字；改過再複製，剪貼簿是改過的內容。
- **評測**（如果改 prompt）：C8 加「不可出現」（決定裡不可有現況、工作分配）；Haiku 4.5 全部案例各 5 次，基準 `20261102-1658`。
- **手動**：實機重新分析 11/2 14:11 那場，複製貼到 LINE，對照 C8 預期的訊息。

## 決定（2026-11-04）

1. 格式 C，依期限分組（使用者選的，不是建議的 A）：問候、【您已決定的事項】、【本週要做的事】、【之後】；別人的待辦放在同一個期限底下，前面標「（麻煩您）」。
2. 入口 2：「⋯」選單的「複製成 LINE 訊息」，開全螢幕預覽（使用者選的，不是建議的 1）。沒有分析時停用。
3. 改 prompt：決議只留真正的決定，現況和工作分配不算。匯出的會議紀錄一起變乾淨；舊會議重新分析才會更新。
4. 用程式組訊息，不多呼叫 AI；待辦改過會反映在訊息裡。
5. 改 prompt：待辦和決議保留工具、產品名稱（TestFlight）。
6. 預覽最上面有稱呼欄，App 記住上次填的，沒填就不寫問候那一行。
7. 分不出誰是使用者（沒填名字或沒勾「我有參加」）時，全部放【本週要做的事】，不出現「麻煩您」；別人的待辦照放「麻煩您」，要改從預覽改。
8. 分析過時時，預覽上方顯示提醒，一樣可以複製。沒有決定和待辦時，入口一樣能按，預覽顯示「這場沒有整理出決定和待辦」。
9. 段落名稱先固定，要改就在預覽裡改。
10. `--budget 0.8`；基準 `20261102-1658`，全部案例各 5 次；整個分支預計約 US$0.4。

## 實作備註

- 格式 C 的代價是 AI 寫的期限不一致時分組會裂開，所以分組前先統一寫法：「星期／禮拜／周」→「週」，去掉「本週／這週」（「本週三前」「週三」都算「週三前」），「本週」「本週內」都算「本週內」。週一到週日依順序排，其他照第一次出現的順序，「沒有期限」最後。
- 分不出誰是使用者時，待辦後面括號寫出 AI 填的負責人，不然這個資訊會不見（決定 7 的補充）。
- 稱呼和內文分開存，改稱呼不會蓋掉改過的內文；按「複製」時才記住稱呼。
- 評測：`FieldKey` 新增 `decisions`（只看決議，不含討論內容）；C8 加「決議不放現況和工作分配」，「TestFlight」只認 TestFlight。
