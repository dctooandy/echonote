# 接續關係的首頁與詳細頁規格

分支：`feature/chain-links`
狀態：開發中（2026-11-01，決定 1～11 確認），待實機確認

跨會議記憶上線後，接續關係只在詳細頁的摘要分頁看得到：首頁看不出哪些錄音是一個系列，詳細頁看不到「被哪幾場接續」，「取消接續」也藏得很深。這個分支讓首頁可以切換「單獨／連動」兩種看法，詳細頁每個分頁都看得到接續關係。示意頁：[接續卡片與標籤](https://claude.ai/artifact/7nY81WzC4gvyp1jnKNigJp)、[單獨／連動](https://claude.ai/artifact/36xZ5UWRQreujCkfQqiyeK)。

## 決定（2026-11-01，使用者依照建議）

1. **規則不變**：有接續上一場的錄音還能被接續；一場可以被好幾場接續；只能接續更早的會議。
2. **系列**：靠接續關係連在一起的錄音（一棵樹：每場最多一個上一場）。系列的名稱用最近那一場的名稱。接續的上一場被刪掉時，這場就是新系列的開頭。
3. **首頁上方切換「單獨／連動」**，記住上次的選擇，第一次預設「單獨」。
4. **單獨檢視**：跟現在一樣一場一場列；日期後面接一行字（H1）：「↩ 接續 10/31」「↪ 2 場後續」，兩個都有時都顯示。
5. **連動檢視（L1 系列分組框）**：
   - 只列有接續關係的錄音；每個系列一個系列顏色的框，框頂寫系列名稱、場數、最近日期。
   - 系列由「最近有錄音的」排到最上面；框裡的錄音由新到舊。
   - 最下面一行小字「另有 N 場沒有接續，在單獨檢視」（N 是 0 時不顯示）。
   - 每一列跟單獨檢視一樣：點進詳細頁、左滑刪除（先確認）。
6. **系列顏色**：青 `#6FD3E0`、紫 `#B39DFF`、粉 `#FF8FB8`、藍 `#7FB2FF`、黃綠 `#C6E07A` 輪流（淺色模式用同色相的深一點版本），避開「已完成」綠、「待分析」琥珀、刪除紅。分配方式見待確認 1。
7. **詳細頁的接續卡片（D3）**：固定在標題下、分頁上，每個分頁都看得到；沒有上一場也沒有後續時不顯示。
   - 收起：一列「↩ 接續 <上一場名稱> · ↪ N 場後續 ▾」，用系列顏色。
   - 展開：上一場一列（點了打開、✏️ 更換、✕ 取消接續），每一場後續一列（點了打開）。
   - 取代現在摘要分頁頂端的「接續：…」卡片；接續的會議被刪掉時，顯示「接續的會議已刪除」，點了重新選擇（跟現在一樣）。
8. **取消接續**：先確認「取消接續『<名稱>（日期）』？只會解除這兩場的關係，不會刪除錄音。這場的『與上次相比』要重新分析後才會更新。」確認後 `previousRecordingId` 設成 null；已分析的話標成「可能過時」（`previousChangedSinceAnalysis`，跟現在換上一場一樣）。

## 目標與範圍

- 上面 1～8。
- 「⋯」選單的「接續上一場」保留（沒有接續的錄音從這裡開始接續）。

**明確不做的事**：

- 不改接續的規則、資料格式和分析。
- 不做系列的改名、手動指定顏色。
- 不在錄音畫面（開始錄音前）選接續。

## 邊界案例與例外處理

- **接續的會議被刪掉**：這場變成新系列的開頭；詳細頁顯示「接續的會議已刪除」。原本的系列可能分成兩個，顏色依待確認 1 的規則決定。
- **只有兩場的系列**、**分岔**：都照決定 5 顯示。
- **連動檢視沒有任何系列**：顯示「還沒有接續的會議。在會議的「⋯」選單選「接續上一場」就能串起來」。
- **在連動檢視刪掉一場**：系列重新計算（可能分成兩個或剩一場而消失）。
- **後續很多場**：展開後全部列出，不限數量。

## 測試接縫

- **純函式**：`followersOf`（多場後續、被刪掉的上一場）、`seriesOf`（分組、分岔、單獨的不算、排序、名稱用最近那場、顏色序號穩定）。
- **widget 測試**（注入記憶體版 store）：
  - 首頁切換單獨／連動、記住選擇；單獨檢視的接續文字；連動檢視的系列框、場數、「另有 N 場」。
  - 詳細頁：卡片收起／展開、每個分頁都在、取消接續先確認且取消時不改、確認後清掉接續並標成過時。
- **手動**：實機看顏色在淺色、深色模式的效果。
