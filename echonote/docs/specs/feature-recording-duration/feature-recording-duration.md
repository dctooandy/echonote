# 首頁顯示錄音時長 規格

分支：`feature/recording-duration`
狀態：已確認（2026-10-22，4 項待確認事項皆採建議答案，見「已確認的方向」6～9）

首頁清單每一筆目前只顯示標題和建立時間，看不出這段錄音有多長。這份規格讓每一筆在日期後面顯示錄音時長。

## 現況（寫規格時查過的程式碼）

- **紀錄格式**（`lib/models/recording.dart`）：`Recording` 沒有時長欄位，`elapsed_seconds` 是**轉錄花的時間**，不是錄音長度。
- **首頁**（`lib/screens/home_screen.dart`）：`ListTile` 的副標題是 `'${createdAt.toLocal()}'.split('.').first`。清單由 `RecordingStore.loadAll()` 一次讀入。
- **即時錄音**（`lib/screens/live_record_screen.dart`）：存檔時已經有 `result.audioDuration`（從寫入的 PCM 計算，準確），目前只用來夾住筆記時間。
- **匯入**（`lib/screens/import_screen.dart`）：只接受 m4a、mp3、wav（`home_screen.dart` 的 `allowedExtensions`），目前沒有讀時長。
- **播放器**：詳細頁用 `just_audio`，`setFilePath()` 會回傳時長。

## 目標與範圍

- `Recording` 新增錄音時長（毫秒，可以是空值，代表「還不知道」）。
- **即時錄音**：存檔時寫入 `result.audioDuration`。
- **匯入**：複製檔案後讀一次時長，跟紀錄一起存。讀不出來就留空，不影響匯入。
- **舊紀錄補時長**：首頁載入清單後，對沒有時長的紀錄**逐筆**讀錄音檔，讀到就寫回紀錄並更新畫面。
- **首頁顯示**：時長放在右邊狀態下面；副標題只放日期（見 UI／畫面）。

**明確不做的事**：

- 詳細頁顯示時長（播放器已經有進度條和總長度）。
- 依時長排序或篩選。

## API 異動

新增「讀錄音檔時長」的小服務（暫定 `AudioDurationProbe`）：給一個檔案路徑，回傳時長或 `null`（讀不出、檔案不存在）。實作用 `just_audio` 的 `AudioPlayer.setFilePath()` 取得時長後立刻釋放播放器（決定 6）。可以注入假的實作供測試。

## 資料表異動

`history/<id>.json` 新增欄位 `duration_ms`（整數，可省略）：

- 舊檔案沒有這個欄位，讀進來是空值，不會出錯。
- 舊版 App 讀到新檔案會忽略這個欄位（`fromJson` 只讀認得的欄位），所以退回舊版不受影響。

## 邊界案例與例外處理

- **錄音檔不存在**（例如之前刪除失敗、搬移裝置）：讀不出，只顯示日期，不報錯。
- **讀不出時長的紀錄每次開首頁都會再試一次**：要，不另外記失敗（決定 8）。
- **補讀進行中使用者離開首頁、刪除或打開某一筆**：補讀只寫回時長欄位，但寫回的是**整筆紀錄**，可能蓋掉詳細頁剛存的修改（例如逐字稿編輯）。寫回前要重新讀那一筆最新的檔案，只更新時長（決定 9）。
- **很多筆舊紀錄**：逐筆讀，不同時開很多播放器；每讀完一筆就更新那一行。
- **未滿 1 秒的錄音**：即時錄音未滿 1 秒不會存檔；匯入的極短檔案顯示 0:01（決定 7）。

## 測試接縫

- **格式化**：純函式（暫定 `formatDuration`），單元測試涵蓋 0 秒、59 秒、59:59、1:00:00、四捨五入或捨去的邊界。
- **紀錄格式**：`duration_ms` 讀寫往返；舊 JSON 沒有這個欄位時為空值。
- **補讀**：用假的 `AudioDurationProbe`，測「沒時長的會補上並存檔」「已有時長的不再讀」「讀不出的維持空值、不存檔」「寫回時不蓋掉其他欄位」。
- **首頁**：widget 測試確認副標題有時長和沒時長兩種顯示。
- **即時錄音**：沿用現有錄音畫面測試，確認存檔的紀錄有時長。
- **實機**：舊紀錄打開首頁後補上時長，和詳細頁播放器的總長度一致；新錄音、匯入 m4a／mp3／wav 都有時長。
