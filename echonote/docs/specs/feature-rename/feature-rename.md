# 會議改名規格

分支：`feature/rename`
狀態：已完成（2026-11-02，決定 1～8 確認，實機確認），待併入 master

會議的名稱現在只能是 AI 分析出的標題（還沒分析就是錄音檔名），使用者改不了；AI 取錯或太長時只能將就。這個分支讓每一場會議都能長按改名。需求是 2026-11-01 討論 `feature/chain-links` 時定的（該規格決定 18）。

## 現況（寫規格時查過的程式碼）

- `Recording.displayTitle`（`lib/models/recording.dart`）：有分析且標題不是空的就用 `analysis.title`，否則用 `audioName`。
- 用到 `displayTitle` 的地方：首頁卡片、系列名稱的預設值、詳細頁 AppBar（`MeetingDetailScreen`）、接續卡片、取消接續確認、刪除確認、逐字稿匯出檔名、HTML 匯出（標題、檔名、「接續：…」）、送給分析的前一場 `title`（`toPreviousMeetingPayload`）。
- 「紀錄」分頁最上面的標題直接讀 `analysis.title`（`meeting_detail_screen.dart` 的 `_buildMinutesTab`）。
- 重新分析會整份換掉 `analysis`，所以直接改 `analysis.title` 會被蓋掉。
- 首頁卡片：點一下打開、左滑刪除，長按目前沒有用途；詳細頁 AppBar 標題長按也沒有用途。

## 決定（2026-11-01 已確認）

1. **能長按改名的地方**：首頁「全部」裡的每一場（包括沒有接續的單獨錄音）、「系列」框裡的每一場、詳細頁最上面的標題。改完兩邊同步。
2. **另存自訂名稱**：`Recording` 新增選填 `customTitle`（JSON `custom_title`）；有就優先顯示，重新分析不會覆蓋；清空就恢復成 AI 的標題（沒分析就是錄音檔名）。
3. **匯出 HTML 也用自訂名稱**（標題、檔名、「接續：…」）。

## UI／畫面

- 對話框輸入框預設帶目前的名稱，下面小字見待確認 3。

## 邊界案例與例外處理

- **名稱前後空白**：去掉；只有空白等於清空。
- **跟 AI 標題一樣**：等於清空（不另存一份一樣的）。
- **還沒分析的會議改名，之後才分析**：分析完仍然顯示自訂名稱。
- **系列名稱沒有自訂時**：用最近那一場的名稱，所以會跟著這場的自訂名稱變。
- **寫檔失敗**：SnackBar「改名失敗」，名稱不變。

## 測試接縫

- **純函式／模型**：`displayTitle` 的優先順序；`customTitle` 的 JSON 讀寫；設定名稱的規則（去空白、空白清空、跟 AI 標題相同清空）。
- **widget 測試**：首頁「全部」和「系列」卡片長按改名並存檔；詳細頁標題長按改名、AppBar 跟著變；清空恢復 AI 標題；重新分析後自訂名稱還在。
- **手動**：實機長按首頁卡片和詳細頁標題各改一次、清空一次，再匯出 HTML 看標題和檔名。
