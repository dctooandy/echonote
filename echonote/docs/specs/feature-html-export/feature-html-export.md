# 會議紀錄匯出成 HTML 規格

分支：`feature/html-export`
狀態：已完成（2026-11-01，決定 1～13 確認；樣式選 B；實機確認），待併入 master

把一場已分析的會議匯出成一個 HTML 檔，用系統分享選單傳給同事（LINE、Email、存到檔案、AirDrop），對方不用裝 EchoNote，用瀏覽器就能看。同時補上跨會議記憶留下的待辦：「複製摘要」要包含「與上次相比」。這是 2026-10-30 定案路線的第 ④ 步；入口放「⋯」選單是使用者 10/31 決定的。

## 現況（寫規格時查過的程式碼）

- `lib/screens/meeting_detail_screen.dart`：
  - 「⋯」選單（`_MoreAction`）：接續上一場、重新分析、用目前詞庫重新轉錄、刪除。
  - 逐字稿匯出 `_exportTranscript`：寫到 `getTemporaryDirectory()` 的 `.txt`，檔名用 `displayTitle` 去掉不合法字元，再用 `SharePlus.instance.share(ShareParams(files: …))` 打開分享選單；失敗時 SnackBar「匯出失敗」。
  - 「複製摘要」：`[overview, ...keyPoints.map('• …')]`，不含待辦、紀錄、與上次相比。
- 資料（`lib/models/recording.dart`）：`MeetingAnalysis` 有 overview、keyPoints、todos（task、owner、dueDate、done、sourceTimestampMs）、title、attendees、agendaItems（topic、discussion、decisions、sourceTimestampMs）、highlightContexts、followUp（todoProgress、decisionChanges、newTopics）。`Recording` 有 notes（使用者筆記）、segments、previousRecordingId。
- 已安裝 `share_plus`、`path_provider`，不用新增套件。

## 目標與範圍

1. 「⋯」選單新增「匯出會議紀錄」，產生一個 HTML 檔並打開分享選單。
2. HTML 是單一檔案：CSS 內嵌，不載入任何外部資源（字型、圖片、script），離線也能看；手機和電腦都好讀；可以列印（iOS 分享選單的「列印」也能存成 PDF）。
3. 內容和順序見待確認 1～4。
4. 「複製摘要」加上「與上次相比」（有的時候才加）。
5. 產生 HTML 的程式是純 Dart 函式，可以單獨測試。

**明確不做的事**：

- 不做 PDF、Word、Markdown 等其他格式。
- 不上傳、不產生分享連結；只交給系統分享選單。
- 不做匯出設定畫面（要不要包含某些段落，見待確認 2、3）。
- 不改分析和資料格式。

## 邊界案例與例外處理

- **會議名稱有 `/`、`:` 等字元**：檔名沿用 `_exportTranscript` 的規則替換掉。
- **內容有 `<`、`&`、引號**（逐字稿、待辦、筆記都是使用者或模型的文字）：一律做 HTML 跳脫，不能讓內容變成標籤或 script。
- **分析之後逐字稿或接續的前一場有變動**（App 已經會顯示「分析可能過時」）：見待確認 7。
- **沒有待辦、沒有決議、沒有與上次相比**：那一段整段不出現，不顯示空標題。
- **寫檔或分享失敗**：SnackBar「匯出失敗」，跟逐字稿匯出一致。
- **使用者在分享選單按取消**：什麼都不做。

## 測試接縫

- **純函式** `buildMeetingHtml(recording, {previous, exportedAt})`（`lib/services/meeting_html.dart`）：
  - 各段落有資料時出現、沒資料時不出現。
  - HTML 跳脫：內容含 `<script>`、`&`、引號時，輸出裡是跳脫後的文字。
  - 不含任何外部網址（`http`、`//`）。
  - 待確認 2、3 的包含／不包含規則。
- **純函式** `summaryCopyText(analysis)`：有／沒有與上次相比時的文字。
- **widget 測試**：「⋯」選單有「匯出會議紀錄」，沒分析時的狀態（待確認 6）；分享本身用注入的假函式，不真的打開分享選單。
- **手動**：實機匯出，用 LINE 傳給自己、存到檔案用 Safari 打開、列印預覽各看一次；淺色和深色模式各看一次。

## 決定（2026-11-01 確認，依照建議）

1. 段落順序：會議名稱、日期、時長、出席者 → 摘要（總覽＋重點）→ 與上次相比（有的時候）→ 待辦 → 會議紀錄（議題、討論、決議）→ 頁尾「由 EchoNote 產生」、匯出時間，以及「內容由 AI 根據錄音整理，請以實際討論為準」（使用者 2026-11-01 同意加上）。
2. 不放使用者的筆記和 AI 補充說明。
3. 不放完整逐字稿。
4. 不顯示時間戳記。
5. 待辦顯示 ☑／☐，完成的加刪除線，匯出當下的狀態。
6. 沒分析的會議：選單項目顯示但變灰。
7. 分析過時照樣匯出，不提示。
8. 與上次相比寫「接續：<前一場名稱>（日期）」；前一場被刪掉時不寫。
9. **樣式固定一種，不給使用者設定**（使用者補充）。從三種範例（[示意頁](https://claude.ai/artifact/EvB8UHGkYa7W3D9KpGCyRP)：A 文件式、B 卡片式、C 精簡清單式）選了 **B 卡片式**：跟 App 一樣的圓角卡片，「與上次相比」用淺青底色，狀態用彩色標籤；列印時改成白底黑字。系統字型、不載入網路資源，支援淺色／深色（跟著系統）、手機寬度、列印。
10. 檔名 `<會議名稱>_<YYYY-MM-DD>.html`。
11. 複製摘要的與上次相比：純文字，分上次待辦、決議變化、新主題三段。
12. LINE 等管道能不能直接打開 `.html`，實機測試時記錄，這一版不處理。
    - 2026-11-01 實機結果：**LINE 不行**（分享時顯示「含有無法分享的檔案」）；AirDrop 到 Mac、Email 都能正常打開。使用者決定這一版不處理；之後常用 LINE 傳，再另開分支做「匯出成 PDF」。
13. 與上次相比的狀態文字共用 App 卡片的（已完成／進行中／這次沒提到；延續／修改／推翻）。
