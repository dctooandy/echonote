# 我的名字（讓 AI 知道逐字稿裡的「我」是誰）規格

分支：`feature/my-name`
狀態：已完成（2026-11-02，prompt 第 3 版已部署、實機確認），待併入 master

週一進度會議演練（C8，私人案例）發現：決定都抓得到，但**待辦負責人幾乎全錯**。手機上那次 11 筆負責人全是空的；評測 3 次中，有一次 7 筆 Andy 的待辦都寫成「陳醫師」。原因是逐字稿沒有說話者，Andy 說的是「我週三前修好」，AI 不知道「我」是誰；整場只有 Andy 叫了一次「陳醫師」，AI 就把他當成負責人。寫錯人比留空更糟（LINE 訊息傳出去會誤會），而且之後的 `feature/meeting-to-line`、週報都依賴負責人正確，所以先做這個。

## 現況（寫規格時查過的程式碼）

- App 不知道使用者的名字：設定（`lib/services/settings_store.dart`、`app_settings.dart`）只有主題、慣用手、首頁檢視、即時文字。
- 分析請求（`lib/services/analysis_request.dart` 的 `buildAnalysisRequest`）：`segments`、`glossary`、`highlights`、`previous_meetings`。只有詳細頁（`meeting_detail_screen.dart` 第 146 行）會呼叫分析。
- `validateRequest`（`functions/src/analyze.ts`）不擋不認識的欄位：App 先送新欄位、function 還沒部署時只會被忽略。
- schema 的 `owner` 說明是「逐字稿中提到的負責人，無法判斷則 null」；prompt 第 224 行「attendees……無法判斷，回傳空陣列，不要猜測」。
- 設定頁分成「外觀」「操作」「其他（詞庫）」三段。
- C8 評測（`20261102-1548`，Haiku 4.5，3 次）：待辦負責人 8 項中 7 項 0/3，「試用商家聯絡方式」1/3。

## 目標與範圍

1. 設定頁可以填「我的名字」（例如 Andy）。
2. 分析時把名字送給 function；prompt 說明逐字稿是使用者錄的，使用者說「我來做」「我負責」時，負責人寫這個名字。
3. 分不出是誰要做時，負責人留空；不可把「被叫到名字的人」當成負責人，除非逐字稿明確說是他要做。
4. 沒填名字時，送出的請求和 prompt 行為跟現在一樣（只多第 3 點的規則）。
5. 用 C8 量修改前／後，其他案例不可以變差。

**明確不做的事**：不做說話者辨識（diarization）、不做每場會議的與會者名單（決定 4，看 C8 結果再說）、不改既有會議（重新分析才會用到名字）。

## 邊界案例與例外處理

- **名字跟詞庫的詞一樣**（例如詞庫也有 Andy）：沒有衝突，照樣送。
- **名字被轉錄成別的字**：例如有人叫「安迪」，見待確認 5。
- **對方也說「我」**：例如陳醫師說「我請行銷給你」。逐字稿沒有說話者，AI 只能看上下文；分不出來就留空（目標 3）。
- **使用者不是發言者**（例如錄別人的會議）：名字仍會送；prompt 寫「逐字稿裡使用者說的『我』」，沒有使用者發言的會議就不會對到，見待確認 6。
- **出席者**：要不要把使用者自己列進出席者，見待確認 7。
- **寫入設定失敗**：SnackBar「儲存失敗」，名字不變。

## 測試接縫

- **function**：`validateRequest` 接受／拒絕 `my_name`；`buildUserMessage` 有名字時多一段、沒有時跟現在一模一樣；`SYSTEM_PROMPT` 有「我」對到名字、分不出來留空、不可把被叫到的人當負責人的句子。
- **App**：`SettingsStore` 讀寫 `my_name`；`buildAnalysisRequest` 帶名字時有 `my_name`、沒有時沒有這個欄位；設定頁填名字、清空。
- **評測**：C8 的 `request.json` 加上 `my_name: "Andy"`；Haiku 4.5 修改前（沿用 `20261102-1548`）／後，C8 各 3 次、其他案例各 5 次。
- **手動**：部署後在設定填名字，重新分析 C8 那場（11/2 14:11），看負責人。

2. 名字最多 20 字（跟詞庫的詞一樣）。

## 實作備註

- function：`my_name`（`MY_NAME_MAX_CHARS = 20`）；有名字時加進送出的詞庫、另開 `<my_name>` 一段。prompt 規則：發言前點出的說話者就是「我」；`<my_name>` 只代表使用者可能在場；兩個以上其他人被點名、使用者名字沒出現時不可對到使用者（第 3 版硬性規則）；不確定填 null。
- App：設定「個人 › 我的名字」（`AppSettings.setMyName`，存 `settings.json` 的 `my_name`）；`Recording.attended`／`iAttended`；詳細頁「⋯ › 我有參加」（小字：「只有你在會議裡發言才打勾，不然 AI 可能把別人的工作寫成你」），切換後已有分析就問要不要重新分析，沒填名字就提示去設定。
- 匯出評測案例工具（`tool/export_eval_case.dart`）照 App 的規則帶 `my_name`。
- 評測：`todos[].owner_none_of`（負責人不可是某人）。
